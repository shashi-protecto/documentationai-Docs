---
title: Unmask with Policy
description: >-
  Apply a named policy during unmasking to control re-identification behavior
  and enforce governance rules.
---
Include `policy_name` in the unmask request to apply a specific policy's metadata during unmasking. This is used in governance-controlled workflows where re-identification must follow defined rules.

## Endpoint details

METHOD: PUT

| Method | Route      | Headers                                 |
| ------ | ---------- | --------------------------------------- |
| PUT    | ` /unmask` | `Authorization: Bearer YOUR_AUTH_TOKEN` |

To get the Authkey please contact [help@protecto.ai](mailto:help@protecto.ai)

## Request body

<ParamField body="policy_name" param-type="string" required="false" deprecated="false">
  The name of the policy to apply during unmasking. If omitted, the default namespace policy applies.
</ParamField>

<ParamField body="unmask" param-type="array" required="true" deprecated="false">
  List of tokenized values to unmask.
</ParamField>

<ParamField body="unmask[].token_value" param-type="string" required="true" deprecated="false">
  The tokenized text to unmask.
</ParamField>

## Notes

- `policy_name` is **optional**. If provided, unmasking uses that policy's metadata and permission rules. If omitted, the default namespace policy applies.

- The policy must exist in your namespace. A missing policy name results in an authorization error.

- See [Policies](/core-concepts/policies) for a conceptual overview of how policies govern unmasking behavior.
