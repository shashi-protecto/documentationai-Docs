---
title: Create Policy
description: Create a new named policy in the namespace with default entity metadata.
---
Creates a new policy in the namespace with default metadata. After creation, update the policy to configure entity categories and masking behavior.

## Endpoint

| Method | Endpoint                                            |
| ------ | --------------------------------------------------- |
| `PUT`  | `https://<domain>/api/vault/metadata/policy/create` |

## Authentication

<ParamField header="Authorization" param-type="string" required="true" deprecated="false">
  Namespace admin bearer token. Format: `Bearer <NAMESPACE_ADMIN_API_KEY>`
</ParamField>

## Request body

<ParamField body="policy_name" param-type="string" required="true" deprecated="false">
  Unique policy name within the namespace.
</ParamField>

<Request show-lines="true" tabs={[]}>
  ```bash
  curl -X PUT https://<domain>/api/vault/metadata/policy/create \
    -H "Authorization: Bearer <NAMESPACE_ADMIN_API_KEY>" \
    -H "Content-Type: application/json; charset=utf-8" \
    -d '{
      "data": {
        "policy_name": "customer-support-policy"
      }
    }'
  ```
</Request>

<Response show-lines="true" tabs={[]}>
  ```json
  {
    "data": {
      "message": "customer-support-policy created successfully."
    },
    "success": true,
    "error": { "message": "" }
  }
  ```
</Response>

## Notes

- Policy names must be unique within the namespace

- If the policy already exists, the API returns an error — use [Update Entity Categories](/policy-management/update-entity-categories) to modify existing policies

- All supported entities default to **pseudonymizable** upon creation

- Use `policy_name` in Mask and Unmask API calls to apply this policy
