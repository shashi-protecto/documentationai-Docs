---
title: Scan for Personal Data Entities
description: >-
  Identify personal data elements — names, email addresses, phone numbers, and
  more — within free-form text without masking the original values.
---
Use this endpoint when you need to **locate and classify** PII in text without replacing or tokenizing it. The API returns each detected entity with its type and exact character positions in the original string.

## Endpoint

| Method | URL                                     |
| ------ | --------------------------------------- |
| PUT    | `https://<BASE_URL>/pii-identification` |

## Authentication

Include your auth token in the request header:

```
Authorization: Bearer <AUTH_TOKEN>
```

## Request body

<ParamField body="data" param-type="array" required="true" deprecated="false">
  List of text inputs to scan for personal data entities.
</ParamField>

<ParamField body="data[].value" param-type="string" required="true" deprecated="false">
  Free-form text to analyze. Each entry is scanned independently.
</ParamField>

## Supported PII types

| `pii_type`      | Description                                               |
| --------------- | --------------------------------------------------------- |
| `PERSON`        | Full or partial personal names                            |
| `EMAIL_ADDRESS` | Email addresses                                           |
| `PHONE_NUMBER`  | Phone numbers in any international format                 |
| `ADDRESS`       | Street addresses, cities, states, and country identifiers |
| `NATIONALITY`   | Nationalities and demonyms                                |
| `URL`           | Website URLs and domain names                             |

## Notes

- Input entries with no detectable PII return an empty `identified_entities` array — they are not omitted from the response.

- `start_pos` and `end_pos` are zero-based character offsets into the original `value` string.

- This endpoint identifies PII only — it does not mask or tokenize values. To mask identified entities, use the [Identify and Mask](./identify-and-mask) endpoint instead.
