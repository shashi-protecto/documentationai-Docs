## Overview

Protecto uses secure authentication to ensure only authorized access to your data protection APIs. You can authenticate requests using API keys for simple integrations or bearer tokens for more advanced session management. All methods require HTTPS and follow standard header-based authorization.

<Callout kind="alert">
Never expose your API keys or tokens in client-side code, public repositories, or logs. Use environment variables and secret management tools.
</Callout>

## Authentication Methods

Protecto supports two primary methods. Choose based on your use case: API keys for direct API calls, or bearer tokens for user-specific sessions.

<Tabs>
  <Tab title="API Key" icon="key">

    Use your API key in the `Authorization` header as `ApiKey YOUR_API_KEY`.

    <ParamField header="Authorization" param-type="string" required="true">
      Format: `ApiKey your-api-key-here`.
    </ParamField>

    <CodeGroup tabs="JavaScript,Python,cURL">
      ```javascript
      const response = await fetch('https://api.example.com/v1/detect', {
        method: 'POST',
        headers: {
          'Authorization': 'ApiKey your-api-key-here',
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({ text: 'Sample PII data' })
      });
      ```
      ```python
      import requests

      headers = {
          'Authorization': 'ApiKey your-api-key-here',
          'Content-Type': 'application/json'
      }
      response = requests.post(
          'https://api.example.com/v1/detect',
          headers=headers,
          json={'text': 'Sample PII data'}
      )
      ```
      ```bash
      curl -X POST https://api.example.com/v1/detect \
        -H "Authorization: ApiKey your-api-key-here" \
        -H "Content-Type: application/json" \
        -d '{"text": "Sample PII data"}'
      ```
    </CodeGroup>

  </Tab>
  <Tab title="Bearer Token" icon="shield">

    Exchange credentials for a bearer token, then use it in the `Authorization` header.

    <ParamField header="Authorization" param-type="string" required="true">
      Format: `Bearer your-token-here`.
    </ParamField>

    <CodeGroup tabs="JavaScript,Python,cURL">
      ```javascript
      // First, get token
      const tokenResponse = await fetch('https://api.example.com/v1/auth/token', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          client_id: 'YOUR_CLIENT_ID',
          client_secret: 'YOUR_CLIENT_SECRET'
        })
      });
      const { access_token } = await tokenResponse.json();

      // Use token
      const response = await fetch('https://api.example.com/v1/detect', {
        headers: { 'Authorization': `Bearer ${access_token}` }
      });
      ```
      ```python
      import requests

      # Get token
      token_data = {
          'client_id': 'YOUR_CLIENT_ID',
          'client_secret': 'YOUR_CLIENT_SECRET'
      }
      token_response = requests.post(
          'https://api.example.com/v1/auth/token',
          json=token_data
      )
      access_token = token_response.json()['access_token']

      # Use token
      headers = { 'Authorization': f'Bearer {access_token}' }
      response = requests.post('https://api.example.com/v1/detect', headers=headers)
      ```
      ```bash
      # Get token
      TOKEN=$(curl -X POST https://api.example.com/v1/auth/token \
        -H "Content-Type: application/json" \
        -d '{"client_id": "YOUR_CLIENT_ID", "client_secret": "YOUR_CLIENT_SECRET"}' \
        | jq -r .access_token)

      # Use token
      curl -X POST https://api.example.com/v1/detect \
        -H "Authorization: Bearer $TOKEN"
      ```
    </CodeGroup>

  </Tab>
</Tabs>

## Generating API Keys

Follow these steps to create and manage your API keys from the Protecto dashboard.

<Steps>
  <Step title="Log In" icon="log-in">
    Access your account at `https://dashboard.example.com`.
  </Step>
  <Step title="Navigate to Keys" icon="key">
    Go to **Settings > API Keys**.
  </Step>
  <Step title="Create Key" icon="plus">
    Click **Generate New Key**, add a description, and select permissions.
  </Step>
  <Step title="Copy and Secure" icon="copy">
    Copy the key immediately—it won't be shown again. Store it securely.
  </Step>
</Steps>

## Permissions and Roles

API keys inherit permissions from roles assigned in your organization. Common roles include:

| Role          | Capabilities                          |
|---------------|---------------------------------------|
| Admin        | Full access: manage keys, policies   |
| Developer    | API calls: detect, mask data         |
| Viewer       | Read-only: view classifications      |

<Expandable title="Advanced Role Management" default-open="false">
  Use the roles API to assign granular permissions programmatically.

  ```javascript
  await fetch('https://api.example.com/v1/roles/assign', {
    method: 'POST',
    headers: {
      'Authorization': 'ApiKey your-api-key-here',
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      user_id: 'user-123',
      role: 'developer',
      permissions: ['detect', 'mask']
    })
  });
  ```
</Expandable>

## Security Best Practices

- Rotate keys every 90 days or after potential exposure.
- Use least-privilege roles—avoid admin keys in production code.
- Monitor usage logs for anomalies.
- Implement token refresh for long-running sessions.

<Callout kind="tip">
Test authentication with a simple `GET /v1/health` endpoint before integrating into production.
</Callout>
